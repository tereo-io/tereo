# Contributing

Thanks for helping with Tereo. Bug reports, fixes and documentation are all welcome. For a new
feature or a change to how core behaves, open an issue first so the approach can be agreed before
you write it.

Security problems go through [SECURITY.md](SECURITY.md), not an issue.

## Getting set up

[README.md](README.md) covers running core and the admin UI locally (*Develop locally*) and running
the test suite. The per-area notes in [packages/tereo/docs](packages/tereo/docs) explain how each
part of core works, and [CLAUDE.md](CLAUDE.md) lists the conventions the code follows.

## Making a change

- **Style** is checked by CI: [docs/code-style.md](docs/code-style.md). Before pushing, run

  ```sh
  npm run format && npm run sort-imports && npm run lint && npm run check
  ```

- **Tests**: add or change tests with the code. Core's suite runs against real Postgres and Redis,
  with real users and tokens (`npm run test:unit -w tereo` and `npm run test:int -w tereo`, or `docker/test/run.sh`).
- **Migrations** are generated by Prisma (`npx prisma migrate dev --create-only`), with raw SQL
  added only for what Prisma cannot express.
- **Version plans**: a change to `@tereo-io/sdk`, `tereo` or `tereo-ui` needs one. Run
  `npm run version-plan` and commit the file it writes. CI's version-plan check says when one is
  missing ([Releases](docs/code-style.md#releases)).
- **Commit messages** follow [Conventional Commits](https://www.conventionalcommits.org/):
  `fix(auth): …`, `feat(files): …`, `docs: …`.

Open the pull request against `master` and fill in the template.

## What belongs elsewhere

- **Integrations with external APIs** belong in
  [dianemo-plugins](https://github.com/dianemo/dianemo-plugins), not in core.
- **Admin UI components** come from [`@kosmeo-ui/react`](https://github.com/kosmeo-ui/kosmeo-ui).
  A change to a component goes there.
