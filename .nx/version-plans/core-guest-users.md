Guest users: temporary logins for customers. A guest is an `auth.users` row with `userType = guest` and an `expiresAt` that is checked live on every sign-in and token path, a `member` of exactly one organization, and limited to org-scoped roles an admin or a provisioning document flagged `guestAssignable` (custom roles only) and, of core's permissions, to `file-service.objects.read` and `write`. `POST /v1/admin/guests` invites, extends and re-shares one account; `PATCH /v1/admin/guests/:id` changes the expiry; `POST /v1/admin/users/:id/promote` makes a guest a permanent user with the same id. A guest sets their first password from a one-time link (`/set-password`, token in the URL fragment, `POST /v1/password-setup`) or is created with a password they must change at first sign-in. New permissions `users.guests.read` and `users.guests.write`, the requestable role `guest_inviter`, a provisioning `guests.defaultRoles` section, `GUEST_MAX_TTL_SECONDS` and `PASSWORD_SETUP_TTL_SECONDS`, and the events `auth.guest.invited`, `auth.guest.extended`, `auth.guest.promoted`, `auth.user.password-setup-link-issued`, `auth.user.password-set` and `auth.role.guest-assignable-changed`. Notifications can be marked sensitive: their content is redacted from the admin log and a retry answers `409 content_redacted`.
