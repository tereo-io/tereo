Fixes from a security and correctness audit of auth, files, provisioning, webhooks and notifications. None needs a migration.

**Authorization and admin.** A guest no longer passes the organization member-tier check: `GET /v1/admin/organizations/:id`, its members and a member's roles answer 403 for guests. Setting `guestAssignable: true` on a role is a grant and needs the caller to be able to grant every permission the role carries. `DELETE /v1/admin/roles/:id/users/:userId?organizationId=` applies the same take-away bound and archived-organization guard as the organization route. Changing a group's roles, archiving or restoring it respects the rule that an organization admin does not manage an owner's roles. Role permission changes, role deletion and identity-provider domain roles re-check their grant bounds under the row lock. Deactivating an identity provider is refused (409) when it would leave no administrator able to sign in. The admin UI's login client cannot lose a scope the UI requires.

**OAuth and sign-in.** `/oauth/token` with `refresh_token_response_mode=cookie` applies the cookie origin rule and answers `403 access_denied` to other origins. `/oauth/authorize` and `/oauth/password-change` charge their failure limiters only for requests that carry a valid flow. Wrong current passwords on `POST /v1/account/password` count against the per-account sign-in backoff. The known-device TOTP allowance is refunded only by the attempt that spent it. Reactivating a user and unlinking a sign-in identity end the user's sessions. Code exchange and organization-bound `client_credentials` re-check the organization under the issuing lock. `/oauth/revoke` clears the refresh cookie only when it revoked that cookie's token. The token endpoint refuses a client whose service is inactive.

**Files.** UUIDs in path, query and body are lower-cased on validation, which fixes multipart parts staged under an upper-cased upload id never being cleaned up, the owner-removal lock and the admin verification-email limiter being keyed by letter case, and webhook secret rotation through an upper-cased id. A buffered download that the client stops reading is dropped after `FILE_SERVICE_VERIFIED_SEND_TIMEOUT_SECONDS` (new, default 120) and a ranged request holds only its range of the read budget. While a bucket's organization is deactivated or archived, share links, the signed URLs they mint and anonymous public-bucket reads answer 404; they serve again on reactivation. Rate-limited requests to `/v1/files/signed` and `/v1/files/shared` no longer write an access-log row. A share cannot pin a `versionId` in a non-versioned bucket (`400 versioning_disabled`). On the object list `filter[contentType]` works and `sort=sizeBytes` keeps its filters; a NUL character in a prefix, filter, metadata or tag is a 400; bulk-delete and archive prefixes escape LIKE wildcards; archive entry names no longer collide for a prefix without a trailing slash. A public bucket's version list shows uploader details only to grant holders. Blobs move across volumes when the temp path is on another filesystem. Multipart 404s are uniform, the thumbnail probe refuses SVG before parsing, multipart part and complete routes accept a trailing slash, and the token-less object routes match case-insensitively.

**Provisioning.** An apply is refused when it would give `admin` to a role a hand-made integration holds, or leave no administrator; a retiring role that would do the latter is kept. Tokens are revoked in the transaction that narrows or removes the access. Row secrets that production cannot open report how to set them again.

**Webhooks and notifications.** Changing an endpoint's `url` to another origin needs its custom header values supplied again (`400 masked_header_value` otherwise). A status-only PATCH on a provisioned endpoint may only set `ACTIVE`. The admin notification detail no longer returns `senderAccess`; delivery errors store the provider's reply or an error code, not the transport message; a notification whose organization is no longer active fails its attachment check. Dead-lettered outbox rows are logged without their payload.

**Pipeline and chart.** A malformed percent-escape in a path is `400 invalid_request`; errors that are not core's own no longer have their 5xx message returned. Redis commands on request paths give up after 2 seconds with `503 temporarily_unavailable` instead of hanging. The chart gains an optional NetworkPolicy (`networkPolicy.enabled`, `networkPolicy.ingressFrom`), off by default.

**Upgrading:** callers that relied on the old behaviour will see the new refusals above — in particular guests on the organization routes (403), cross-origin cookie-mode token requests (403), webhook endpoint origin changes without header values (400; the admin UI's endpoint form does not prompt for them yet), share creation with `versionId` in a non-versioned bucket (400), and shares or public buckets of an inactive organization (404). Clients slower than about 1 Mbit/s downloading a blob near 16 MiB are cut off at the default send timeout and can resume with `Range`; raise `FILE_SERVICE_VERIFIED_SEND_TIMEOUT_SECONDS` if that matters. Part files staged under an upper-cased upload id before this release remain under the storage path's `multipart/` directory and can be removed by hand.
